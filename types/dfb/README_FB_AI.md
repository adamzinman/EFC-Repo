# FB_AI - Analog Input DFB (Control Expert Classic V16.2)

IEC 61131-3 Structured Text DFB that processes a `T_AI` instance. Generated by `gen_dfb.py`.
Edit the code there and re-run it; don't edit these files directly.

## Files

| File | Use |
|---|---|
| `export/PCLib_DFB_AI_CE_V16.2.xdb` | **Import this.** Contains the DDTs `T_Alarm`, `T_AlmLim`, `T_AI` and the DFBs `FB_AlmCore`, `FB_Alarm`, `FB_AlmLim`, `FB_AI`, in dependency order |
| `dfb/FB_*.st` | IEC 61131-3 textual source (`FUNCTION_BLOCK ... END_FUNCTION_BLOCK`) for review, version control and portability |

## Import

1. Project Browser > **Derived FB Types** > right-click > **Import...** > select the `.xdb`.
2. If the DDTs already exist (from `PCLib_CE_V16.2.xdd`), choose **Keep** unless you want this version.
3. **Build > Analyze Project**.

If the `.xdb` import fails, you can build the DFBs by hand: create each DFB in the order `FB_AlmCore`,
`FB_Alarm`, `FB_AlmLim`, `FB_AI`. Enter the variables from the `VAR_*` blocks of the `.st` file
(inputs, in/outs, outputs, private), then paste the code after the last `END_VAR` into an ST section named `Main`.

## Use

```
(* Variables: FT101 : T_AI;  fbFT101 : FB_AI; *)
FT101.Inp_Raw := %IW0.2.0;            (* or the M580 device DDT channel value *)
FT101.Inp_ChFault := NOT %I0.2.0.ERR; (* channel health *)
fbFT101(AI := FT101);
```

Use the DFB in a cyclic (MAST or FAST) task, once per scan. It works out its own elapsed time,
so it is not tied to a particular task period.

## Processing order

| # | Step | Members |
|---|---|---|
| 1 | Elapsed time since last scan (free-running TON, no system calls) | - |
| 2 | Configuration check: raw or EU span of zero makes the PV bad | `Cfg_RawMin/Max`, `Cfg_EUMin/Max` |
| 3 | Raw counts to % of span | `Inp_Raw` |
| 4 | Signal validation: NAMUR NE43 limits, channel fault, device NE107 Failure | `Cfg_BadLoPct/HiPct`, `Inp_ChFault`, `Inp_NE107`, `Sts_URng/ORng` |
| 5 | Square-root extraction, low cut-off, scaling to EU | `Cfg_SqrtExtract`, `Cfg_LoCutoff` |
| 6 | Simulation replaces the field signal, and field faults are ignored | `Sim_En`, `Sim_PV`, `Sts_Sim` |
| 7 | First-order filter. Re-initialised on start-up, bad-to-good recovery and sim change, so there is no bump | `Cfg_FiltTC` |
| 8 | Bad-value action: hold last good / substitute / EUMin / EUMax | `Cfg_BadAction`, `Cfg_SubstPV`, `Sts_Subst` |
| 9 | Quality and NAMUR NE107 status. Simulation reports as C (function check) | `Sts_Quality`, `Sts_NE107` |
| 10 | Rate of change, 1 s window. Re-initialised on recovery and sim change, so there are no false ROC alarms | `Val_ROC` |
| 11 | Alarms: HH/H/L/LL/ROC limit alarms and the bad-PV alarm | `Alm_*` |

## Alarm behaviour (ISA-18.2 / IEC 62682)

`FB_AlmCore` implements the alarm state model and is shared by `FB_Alarm` and `FB_AlmLim`.
Every equipment DFB in the library can reuse it.

- **States** (`Sts_State`): 0 Normal, 1 Unack, 2 Acked, 3 RTN-Unack, 4 Latched, 5 Shelved,
  6 Suppressed-by-design, 7 Out-of-service / disabled.
- **Chattering control:** on-delay and off-delay timers, and a deadband on limit alarms.
- **Latching:** `Cmd_Reset` only clears a latched alarm after the condition has returned to normal.
- **Shelving:** always time-limited by `Cfg_MaxShelf`. If the condition is still present when the shelf
  expires or the alarm is unshelved, it re-annunciates.
- **Suppressed by design:** the HH/H/L/LL/ROC alarms are suppressed while the PV is bad, so the
  operator sees one bad-PV alarm instead of a flood of process alarms.
- **Out of service:** set by `Cmd_RemoveSvc` and cleared by `Cmd_ReturnSvc`.
- **One-shot commands:** `Cmd_` bits are cleared by the DFB after each scan.
- **Performance data:** `Val_Count`, `Val_LastActive` and `Val_LastRTN` support alarm KPI reporting.

**Limit alarms are disabled by default** (`Cfg_En = FALSE`). Enable each one once its limit has
been set from your alarm rationalisation.

## IEC 61131-3 compliance

- **Language:** Structured Text only, with standard declarations (`VAR_INPUT`, `VAR_IN_OUT`,
  `VAR_OUTPUT`, `VAR`), `(* *)` comments, typed variables and initial values.
- **Standard function blocks:** `TON`, `TOF`, `R_TRIG`, `F_TRIG`.
- **Standard functions:** `SQRT`, `ABS`, `INT_TO_REAL`, `DINT_TO_REAL`, plus `TIME` arithmetic.
- **No direct addressing:** no located variables (`%M`, `%MW`), no global variables and no system bits
  inside the DFBs. All data passes through parameters, so the blocks are encapsulated and reusable.
- **Two Control Expert functions:**
  - `TIME_TO_DINT`: TIME-to-number conversion. Standard IEC 61131-3 does not define one.
  - `RRTC_DT`: reads the PLC clock for alarm timestamps.

  If you port the code to another IEC platform, replace these two calls with that vendor's equivalents.

## Test checklist (run in the simulator)

| Test | Expected |
|---|---|
| `Inp_Raw` 5000, range 0..10000, EU 0..200 | `Val_PV` = 100.0, `Sts_Quality` = 0 |
| `Cfg_SqrtExtract`, `Inp_Raw` 2500 | `Val_PV` = 100.0 (50 % of span) |
| `Inp_Raw` -300 (below -2.5 %) | `Sts_Bad`, `Sts_URng`, `Sts_NE107` = 1, `Alm_Bad` active, HH..LL show state 6 |
| `Cfg_BadAction` 0 / 1 / 2 / 3 while bad | PV holds / `Cfg_SubstPV` / EUMin / EUMax |
| `Sim_En` with `Sim_PV` 150 | `Val_PV` 150, `Sts_NE107` = 2, `Sts_Quality` = 1, no `Alm_Bad` |
| `Cfg_FiltTC` 10 s, step input | PV reaches 63 % of the step after about 10 s |
| `Alm_H`: limit 150, deadband 5, enabled | Active above 150; returns to normal at or below 145 |
| Shelve `Alm_H` with `Cfg_MaxShelf` T#10S | `Sts_State` 5, then re-annunciates after 10 s if still active |
