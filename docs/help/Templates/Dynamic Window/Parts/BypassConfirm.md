## Overview

A small modal popup that asks for a reason before one interlock or permissive condition is bypassed, or before its bypass is removed (decision 10, issue #8). Its OK button calls `efc.ui.bypass` or `efc.ui.unbypass`, which re-check everything, write the command and the audit record, and return `''` or the reason they refused. The popup shows that reason instead of closing.

- **Default size:** 360 x 290 (`props.defaultSize`).
- **Popup settings (set by the caller):** id `efcBypass`, `modal=True`, `showCloseIcon=False`. The user leaves only through CANCEL or a successful BYPASS / UNBYPASS.
- **Parameters:** `tagPath` (the `T_Intlk` group, `<device>/Perm` or `<device>/Intlk`), `idx` (condition 0 to 15), `desc` (the condition text to show) and `action` (`'bypass'`, the default, or `'unbypass'`).
- **Generated view:** yes, `bypass_confirm()` in `generator/docks/build_docks.py`.

## How it operates

**Content.** The title is `Remove bypass` when `action` is `'unbypass'`, else `Bypass condition`; the `desc` parameter is the condition text. The note reads "Supervisor or higher. The reason and your user name go to the audit log." and, in bypass mode, adds "The PLC ends the bypass after <n> min (Cfg_BypassMax).", where n = `toInt(Cfg_BypassMax / 60000)` from the mirror `custom.m_Cfg_BypassMax` (`?` while it cannot be read).

**Reason.** A required free-text field, `Reason (required)`. Its text is bound two ways to `view.custom.reason`.

**Error.** A label under the reason shows `view.custom.error`; it is hidden while the text is empty.

**CANCEL.** Closes the popup `efcBypass`. No tag write, no audit.

**BYPASS / UNBYPASS (`Button/Danger`).** The text is `UNBYPASS` when `action` is `'unbypass'`, else `BYPASS`.

- Enabled only when the user's level is 3 (Supervisor) or above and the trimmed reason is not empty. Both are checked by the enable expression.
- On press it calls `efc.ui.unbypass(self, tagPath, idx, reason)` when `action` is `'unbypass'`, else `efc.ui.bypass(...)`, and stores the result in `view.custom.error`. An empty result closes the popup; otherwise the popup stays open and the Error label shows the reason.
- `efc.ui.bypass` checks the level (below 3 it also opens the AccessDenied popup), the reason, `Cfg_Bypassable[idx]` and `Inp_BypassPerm` again, so the enable expression is not the only guard. When all pass it writes `TRUE` to `<tagPath>/Cmd_Bypass/<idx>` (a one-shot command) and writes the audit record `EFC bypass` (target `<tagPath>/<idx>`, value = the reason, actor = the user name).
- `efc.ui.unbypass` checks the level and the reason, writes `TRUE` to `<tagPath>/Cmd_Unbypass/<idx>` and writes the audit record `EFC unbypass` with the reason.

The popup reads `Cfg_BypassMax` only to show it; `efc.ui.bypass` reads `Cfg_Bypassable[idx]` and `Inp_BypassPerm`. The bypass duration is not chosen here: `T_Intlk` has no member to receive a duration, so every bypass runs until `Cfg_BypassMax` (PLC timeout logic, not in this repository) or until it is removed. Durations shorter than `Cfg_BypassMax` (decision 10) are not implemented.

### Library functions called by this view (`efc.ui`, `projects/EFC_Library/ignition/script-python/efc/ui/code.py`)

- **`efc.ui.bypass(component, intlkPath, idx, reason)`**: returns `''` when bypassed, else the reason it refused, with no write and no audit: below level 3 it calls `efc.ui.denied` (WARN log and AccessDenied popup) and returns 'Requires Supervisor access.'; a reason blank after trimming gives 'Enter a reason.'; `Cfg_Bypassable[idx]` false gives 'This condition is not bypassable.'; `Inp_BypassPerm` false gives 'Bypass is not permitted now (Inp_BypassPerm is off).'. Otherwise it writes `TRUE` to `<intlkPath>/Cmd_Bypass/<idx>` through `_writeTags` (a bad write is logged and returns 'The bypass command was not written. See the gateway log.'), writes the audit record `EFC bypass` (target `<intlkPath>/<idx>`, value = reason) and returns `''`. If no audit profile exists, `system.util.audit` fails silently and the record goes to the `efc.ui` logger at INFO level.
- **`efc.ui.unbypass(component, intlkPath, idx, reason)`**: same return convention. Below level 3: AccessDenied popup and 'Requires Supervisor access.'; blank reason: 'Enter a reason.'. Otherwise writes `TRUE` to `<intlkPath>/Cmd_Unbypass/<idx>` (a bad write returns 'The unbypass command was not written. See the gateway log.'), audits `EFC unbypass` with the reason and returns `''`.
- **`efc.ui.level(levels)`**: see the transform above.

## Notes and open questions

1. **Duration is not set here (decision 10, partly open).** Decision 10 asks for a bypass duration up to `Cfg_BypassMax`. `T_Intlk` has no member to receive a duration, so this popup sends none and every bypass runs to `Cfg_BypassMax`. The timeout itself is PLC logic, not in this repository. Confirm it in the PLC program.
2. **The index is not checked against `Cfg_Used`.** `efc.ui.bypass` checks `Cfg_Bypassable[idx]`, but neither it nor `efc.ui.unbypass` checks `Cfg_Used[idx]`. Only the IntlkList row visibility does.
3. **Reason is not stored in the PLC.** It appears only in the audit log.
4. **No free-text rules.** The reason field has no minimum length and no list of approved reasons.
5. **Description is a snapshot.** `desc` is copied when BYPASS or UNBYP is pressed in the row, not read live.
