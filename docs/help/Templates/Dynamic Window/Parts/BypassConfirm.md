## Overview

A small modal popup that asks for a reason before one interlock or permissive condition is bypassed. Its OK button calls `efc.ui.bypass`, which writes the bypass command and the audit record.

- **Default size:** 360 x 260 (`props.defaultSize`).
- **Popup settings (set by the caller):** id `efcBypass`, `modal=True`, `showCloseIcon=False`. The user leaves only through CANCEL or a successful BYPASS.
- **Parameters:** `tagPath` (the `T_Intlk` group, `<device>/Perm` or `<device>/Intlk`), `idx` (condition 0 to 15), and `desc` (the condition text to show).
- **Generated view:** yes, `bypass_confirm()` in `generator/docks/build_docks.py`.

## How it operates

**Content.** A fixed title, `Bypass condition`; the `desc` parameter as the condition text; and a note: "Supervisor or higher. The reason and your user name go to the audit log; the bypass times out at the block's Cfg_BypassMax."

**Reason.** A required free-text field, `Reason (required)`. Its text is bound two ways to `view.custom.reason`.

**CANCEL.** Closes the popup `efcBypass`. No tag write, no audit.

**BYPASS (`Button/Danger`).**

- Enabled only when the user's level is 3 (Supervisor) or above and the trimmed reason is not empty. Both are checked by the enable expression.
- On press it calls `efc.ui.bypass(self, tagPath, idx, reason)`. If that returns True, the popup closes. If it returns False, the popup stays open with no message.
- `efc.ui.bypass` checks the level and the reason again, so the enable expression is not the only guard. When it succeeds it writes `TRUE` to `<tagPath>/Cmd_Bypass/<idx>` (a one-shot command) and writes the audit record `EFC bypass` (target `<tagPath>/<idx>`, value = the reason, actor = the user name).

The popup does not read `Cfg_Bypassable`, `Cfg_BypassMax` or `Inp_BypassPerm`. Bypass duration is therefore not set by this popup. The note says the bypass times out at `Cfg_BypassMax`; the timeout logic is in the PLC and is not in this repository.

Total: **2 event scripts** (`onActionPerformed`) and **1 transform script**. No `customMethods`, `messageHandlers`, property-change scripts or `view.scripts`.

1. **`root/Buttons/Cancel`**: `onActionPerformed`.
   ```python

   ```
   Closes the popup. No tag write.

2. **`root/Buttons/Ok`**: `onActionPerformed`.
   ```python

   	system.perspective.closePopup('efcBypass')
   ```
   Calls `efc.ui.bypass`. The popup closes only when it returns True. The function writes the bypass command and the audit record (see the library function below).

3. **`view custom.level`**: transform on the binding.
   ```python
   return efc.ui.level(value)
   ```
   Converts the user's role list to a level from 0 to 5.

### Library functions called by this view (`efc.ui`, `projects/EFC_Library/ignition/script-python/efc/ui/code.py`)

- **`efc.ui.bypass(component, intlkPath, idx, reason)`**: returns False, with no write and no audit, if the user is below level 3 or the reason is blank after trimming. Otherwise writes `TRUE` to `<intlkPath>/Cmd_Bypass/<idx>` with `system.tag.writeBlocking`, writes the audit record `EFC bypass` (target `<intlkPath>/<idx>`, value = reason), and returns True. If no audit profile exists, `system.util.audit` fails silently and the record goes to the `efc.ui` logger at INFO level.
- **`efc.ui.level(roles)`**: see the transform above.

## Notes and open questions

1. **No check on the index.** The popup does not check `Cfg_Bypassable[idx]`. Only the IntlkList row visibility does. A call with another `idx` would still write `Cmd_Bypass`. Whether the PLC refuses it is not visible here.
2. **Silent failure.** If `efc.ui.bypass` returns False (for example, the user's level changed while the popup was open), the popup stays open with no message. The enable expression prevents this in normal use.
3. **Bypass authorisation not used.** `Inp_BypassPerm` (the key switch or HMI permit in `T_Intlk`) is not read here or in `efc.ui.bypass`. See [IntlkList](./IntlkList.md), note 2.
4. **Duration is not set here.** The note says the bypass times out at `Cfg_BypassMax`. This popup sends no duration, and the timeout is not implemented in this repository. Confirm it in the PLC program.
5. **Reason is not stored in the PLC.** It appears only in the audit log.
6. **No free-text rules.** The reason field has no minimum length and no list of approved reasons.
7. **Description is a snapshot.** `desc` is copied when BYPASS is pressed in the row, not read live.
