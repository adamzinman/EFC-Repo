# Templates/Dynamic Window/IO/IOCard

Source: `projects/EFC_Library/com.inductiveautomation.perspective/views/Templates/Dynamic Window/IO/IOCard/view.json`
Generated by `generator/docks/build_docks.py` (`io_card()`). Change the generator, not `view.json`.
Opened from: the IO card tile `Templates/IO/Parts/SlotTile` (the rack overview's tiles), through `efc.ui.openDynamic`, with `tType` `native` and `dockId` `dw_IOCard`. Dynamic window id `dw_IOCard`. The window opens in the page's right dock, `dw_Right`.
Related templates (their help docs are not written yet): `Templates/IO/RackOverview`, `Templates/IO/Parts/SlotTile`, and the card faceplates `Templates/IO/Faceplates/<model>` (for example `BMXDDI1602`, `BMXAMI0810`), which the FULL FACEPLATE button opens as a popup.

## Overview

A read-only summary of one X80 I/O card: model, rack, slot, card description and the module diagnostic text, with a banner that shows MODULE ERROR, OK, or UNKNOWN when the error bit is null or bad quality. The FULL FACEPLATE button opens the card's own faceplate as a popup. The window has no commands and no role-gated controls.

- **Default size:** 400 x 860 (`props.defaultSize`). The root is a scrolling column (`Container/Scroll`).
- **Parameters:** `tagPath` (the card UDT instance), `tType` (default `native`), and `model` (the card model, for example `BMXDDI1602`).
- **How it is opened:** a single click on the SlotTile runs `efc.ui.openDynamic(self)` when the tile's `model` is set. `openDynamic` maps `dockId` `dw_IOCard` to `Templates/Dynamic Window/IO/IOCard`, takes the tag path from `dwTagPath`, then `tagPath`, then `cardPath` (SlotTile passes `cardPath`), passes `model` along, and loads `Templates/Dynamic Window/IO/IOCard` into the page's `dw_Right` dock with params `{tagPath, model}` (`system.perspective.alterDock`) and opens the dock.
- **Native DDT:** the card is a native x80 device type (`tType` `native`), not a PCLib UDT. See Tag members used.
- **Generated view:** yes, `io_card()` in `generator/docks/build_docks.py`.

## How it operates

**Header.** The title shows `Rack <n> / slot <n>` from the card's `Rack` and `Slot`. The subtitle shows the model (`params.model`). The X button runs `efc.ui.closeDynamic(self)`, which returns the `dw_Right` dock to the page default, or closes it.

**Banner.** `UNKNOWN` (class `State/Unknown`) while `Module/MOD_ERROR` is null or has bad quality (`isNull(...) || !isGood(...)`, tested first). Otherwise `MODULE ERROR` (class `State/Fault`) while `Module/MOD_ERROR` is TRUE, else `OK` (class `State/Running`). The trailing `UNKNOWN` in the expression is the unreachable `if(true, ...)` fallback.

**Card section.** Five rows, each label and value:

- **Model:** `params.model`, from the SlotTile. Blank if none was passed.
- **Rack** and **Slot:** the card's rack and slot numbers.
- **Description:** `CardDesc` from the card UDT. The UDT sets it per model, for example `16 DI · 24 VDC`.
- **Diagnostic:** `Module/HMI/DiagText`, the names of the module-level bits that are set (`MOD_FAIL`, `CH_FLT`, `BLK`, `CONF_FLT`, `NO_MOD`). Blank when none is set.

**FULL FACEPLATE.** Always visible. When `params.model` is set, it opens the popup `io_<tagPath>` on `Templates/IO/Faceplates/<model>`, with `cardPath` = `tagPath`. The popup is draggable, not resizable, not modal, and has no close icon. When `model` is blank, the button does nothing.

**Roles.** None. The `level` custom property is bound to the user's role level, but no binding or script in this view uses it. The faceplate popup is read-only (the IO README says the faceplates never write to the card).

1. **`root/Header/Close`**: `onActionPerformed`.
   ```python

   ```
   Returns the `dw_Right` dock to the page's default view, or closes the dock if there is none.

2. **`root/Card/Body/Full`**: `onActionPerformed`.
   ```python
   model = self.view.params.model
   if model:
   	p = self.view.params.tagPath
   	system.perspective.openPopup('io_' + p, 'Templates/IO/Faceplates/' + model, params={'cardPath': p},
   		title='', showCloseIcon=False, draggable=True, resizable=False, modal=False)
   ```

   Opens the card's faceplate as a non-modal popup, with the popup id `io_` plus the tag path. It does nothing if `model` is blank. It writes no tag and does no role check (the faceplate is read-only).

   ```python
   return efc.ui.level(value)
   ```
   Converts the user's security levels to a level from 0 to 5 (case-insensitive name match, site names through `efc.ui.ROLE_ALIASES`). Its value is not used in this view.

## Tag members used

This view is bound to a native x80 card UDT, not a PCLib `T_` type. The UDT is in `IO Faceplates.zip` (`EFC_IO_UDTs.json`, under `_types_/IO/<card>`), and it is not in `types/` or `tags/` in this repository. The members below are from the `BMXDDI1602` UDT in that file. Other card UDTs have the same top-level members. The card UDTs are described in the zip's README.

|---|---|---|---|
| `Module/MOD_ERROR` | read | Boolean (OPC, from the PLC through the `BMENUA0100` OPC UA connection) | Module error. Drives the banner. |
| `Module/HMI/DiagText` | read | String (expression from `MOD_FAIL`, `CH_FLT`, `BLK`, `CONF_FLT`, `NO_MOD`) | Names of the set module bits. Read-only. |

The UDT also has `CardModel`, which this view does not read (it uses `params.model`), and the channel members `CHxx/*`, which this window does not show.

## Notes and open questions

1. **`custom.level` is bound but unused.** There is no role gating in this window. That is acceptable for a read-only view, but it means the binding does nothing.
2. **Channel faults are not summarised.** The window shows only module-level bits. Channel `CH_ERROR` values and per-channel diagnostics are not shown here; they are on the faceplate.
3. **Diagnostic text lists module bits only.** `Module/HMI/DiagText` names module bits, not channel bits.
4. **FULL FACEPLATE depends on `model`.** SlotTile only calls `openDynamic` when the tile has a model, so a normal open has one. A window opened from some other caller with a blank model shows no faceplate, and the button does nothing with no message.
5. **Popup id.** The faceplate popup id is `io_` plus the card path, so opening the same card's faceplate twice uses the same id. How Perspective handles a second open with the same id is not visible in this repository.
6. **Help for the IO templates is not written.** The `Templates/IO/*` views (rack overview, tile, faceplates) have no files under `docs/help/Templates/IO/` yet, so the faceplate referenced by FULL FACEPLATE is not documented here.
