# Discrete I/O card faceplates

Covers `Templates/IO/Faceplates/BMXDDI1602`, `BMXDDI3202K`, `BMXDDO1602`, `BMXDDO3202K` and `BMXDDO6402K`. These are the 16, 32 and 64 channel discrete input and output card faceplates.
Sources: `projects/EFC_Library/com.inductiveautomation.perspective/views/Templates/IO/Faceplates/<name>/view.json` (five views).
Dock that opens them: [IOCard](../../Dynamic%20Window/IO/IOCard.md) (the `Full` button). Channel tile: [DiscreteTile](../Parts/DiscreteTile.md). Rack view: [RackOverview](../RackOverview.md).

## Overview

- **Default size:** per view, see the table below (`props.defaultSize`).
- **Opened by:** the `Full` button in the `Templates/Dynamic Window/IO/IOCard` dock, as a popup. The dock runs `system.perspective.openPopup('io_' + p, 'Templates/IO/Faceplates/' + model, params={'cardPath': p}, title='', showCloseIcon=False, draggable=True, resizable=False, modal=False)`, where `p` is the dock `tagPath` and `model` is the dock `model` param. The popup id is `io_` plus the card path.
- **Embedded:** no `ia.display.view` in the library points at these views. They are opened by name only.
- **Params:** `cardPath` only.
- **Generated view:** no. The dock `Templates/Dynamic Window/IO/IOCard` is generated by `generator/docks/build_docks.py` (`io_card()`), which contains the `Full` popup call. These faceplate files are not written by any generator; `generator/render_views.py` only lists them on the review sheet, sets their preview `cardPath`, and builds the fixture tags they read.

## How it operates

- **Header.** The model name and description are static text. The `Instance` line shows the last segment of `cardPath`, then `Rack` and `Slot` from the card tags. Blank values are shown as empty text.
- **Module health.** `ModHealth` shows `MODULE HEALTHY` (class `State/Running`) when `Module/MOD_ERROR` is good and false, `MODULE FAULT` (`State/Fault`) when it is true, and `COMMS?` (`State/Unknown`) when the tag quality is bad.
- **Status bar.** `ModDiag` shows `Module: <text>` when `Module/HMI/DiagText` is not empty, otherwise `No module diagnostics active`.
- **Read-only outputs.** The DO views carry the caption `Read-only: the PLC drives these outputs` (`StatusBar/RO`). No binding, script or transform in any of the five views writes a tag. The faceplates show status only.
- **READ_STS caption.** All five show the caption `READ_STS` (`StatusBar/Note`). The source does not explain it. See Notes.
- **Body.** Each body group has a static label (`INPUTS` or `OUTPUTS` with the channel range) and a flex repeater. The repeater builds one `DiscreteTile` per channel from a list made by its transform. Channel `i` gets `ch = i`, `chFolder = CHnn` and `alt = true` on odd channels (row shading). The tile does the per-channel work.
- **Close.** The `Close` button calls `system.perspective.closePopup('')`.
- **Security.** The faceplate has no role check and no audit, because it writes nothing.

None. The components carry no `custom` properties.

## Scripts reference

Each view has one event script (`root/Header/Close`) and one transform script per body repeater (T1). Totals: 2 for DDI1602 and DDO1602 (1 + 1), 3 for DDI3202K and DDO3202K (1 + 2), and 5 for DDO6402K (1 + 4). There are no custom methods, message handlers, onChange scripts or view scripts.

| Location | Kind | Trigger | Views | Explanation |
|---|---|---|---|---|
| `root/Header/Close` | event | `events.component.onActionPerformed`, scope G | all five | Closes the popup. Uses an empty id (see Notes). |
| `root/Body/Group*/Tiles*` (T1) | transform on `props.instances` | Evaluated when `cardPath` changes | every view, one per repeater | Builds the list of channel instances for the repeater. |

Event script, `root/Header/Close`:

```python
	system.perspective.closePopup('')
```

Explanation: `system.perspective.closePopup` with an empty id closes the popup the calling component is in, which is this faceplate (opened by the dock as `io_<cardPath>`).

Transform T1 (same code in all repeaters, only the `range` changes):

```python
	n = 16
	p = str(value or '')
	if not p:
		return []
	return [{'cardPath': p, 'ch': i, 'chFolder': 'CH%02d' % i, 'alt': (i % 2 == 1)} for i in range(0, 16)]
```

Explanation: if `cardPath` is blank, return an empty list. Otherwise return one instance dict per channel in the range, with `cardPath`, `ch` (the channel number), `chFolder` (`CH` plus two digits), and `alt` (true for odd channels). The repeater passes each dict to `DiscreteTile` as its params. `n = 16` is set but never used. The channel count comes from the `range`.

| Repeater | Range (channels) | Views |
|---|---|---|
| `root/Body/Group0/Tiles0` | `range(0, 16)` (channels 00 to 15) | `BMXDDI1602`, `BMXDDI3202K`, `BMXDDO1602`, `BMXDDO3202K`, `BMXDDO6402K` |
| `root/Body/Group1/Tiles1` | `range(16, 32)` (channels 16 to 31) | `BMXDDI3202K`, `BMXDDO3202K`, `BMXDDO6402K` |
| `root/Body/Group2/Tiles2` | `range(32, 48)` (channels 32 to 47) | `BMXDDO6402K` |
| `root/Body/Group3/Tiles3` | `range(48, 64)` (channels 48 to 63) | `BMXDDO6402K` |

No `efc.ui` library function is called from these views. The dock and library are described in the dock doc.

## Tag members used

There is no PCLib UDT for these cards. `types/PCLib_Members.csv` has no entry for `Module/MOD_ERROR`, `Module/HMI/DiagText`, `Rack`, `Slot`, `CardDesc`, `CH*` or `Doc/*`, and `tags/` has no IO tags. The structure below is what these views read. Types are inferred from how the bindings use each member (BOOL for `if`/`isGood` tests, STRING for text, INT for numbers). The fixture in `generator/render_views.py` (`io_fixture`) creates the same members. The channel members (`CHnn/...`) are used by `DiscreteTile`, see [DiscreteTile](../Parts/DiscreteTile.md).

| Member | Access | Data type | Meaning |
|---|---|---|---|
| `Module/MOD_ERROR` | read | BOOL (inferred) | Module error. Drives MODULE HEALTHY / MODULE FAULT. Quality also drives COMMS?. |
| `Module/HMI/DiagText` | read | STRING (inferred) | Module diagnostic text for the status bar. |
| `Rack` | read | INT (inferred) | Rack number in the header. |
| `Slot` | read | INT (inferred) | Slot number in the header. |

Access is read only for all four. The views have no write path.

## Notes and open questions

- **READ_STS caption.** The caption `READ_STS` is static text with no binding. What it refers to is not defined in this repo. Open question.
- **Output commands.** The DO faceplates have no command controls, and the DO tiles do not write either (see DiscreteTile). The RO caption matches this. It is not clear whether output commands are meant to be added here. Open question.
- **Unused variable.** Each transform sets `n = 16` and never uses it. Cosmetic. The channel count is set only by the `range`.
- **Preview default.** All five default to `[default]IO_Demo/Rack0/R0S2`, a preview address. The popup always passes a `cardPath`, so the default is only used when the view is opened with no param (for example from the designer).
- **Model names.** The dock builds the popup path from the model name (`Templates/IO/Faceplates/` + model). Only the five discrete and three analog faceplates exist. Other card models would open a missing view (behaviour not checked at runtime).
- **Dock doc.** [IOCard](../../Dynamic%20Window/IO/IOCard.md) covers the dock.
- **Dock generator and committed JSON.** `generator/docks/build_docks.py` removes the `m_Cfg_Tag` and `m_Cfg_Desc` custom props from the IOCard dock, but the committed `Templates/Dynamic Window/IO/IOCard/view.json` still has tag bindings for them (`propConfig`). The bindings point at members that a native device does not have. This is a defect in the dock, see the dock doc.
