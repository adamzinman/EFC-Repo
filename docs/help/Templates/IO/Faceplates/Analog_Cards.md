# Analog I/O card faceplates

Covers `Templates/IO/Faceplates/BMXAMI0810` (8 AI), `BMXAMO0802` (AO) and `BMXART0814` (8 RTD / TC). Each shows one row per channel, built from an `AnalogRow` part.
Sources: `projects/EFC_Library/com.inductiveautomation.perspective/views/Templates/IO/Faceplates/<name>/view.json` (three views).
Dock that opens them: [IOCard](../../../Docks/IOCard.md) (the `Full` button). Row part: [AnalogRow](../Parts/AnalogRow.md). Rack view: [RackOverview](../RackOverview.md).

## Overview

- **Default size:** per view, see the table below (`props.defaultSize`).
- **Opened by:** the `Full` button in the `Docks/IOCard` dock, as a popup. The dock call is the same as for the discrete faceplates: `system.perspective.openPopup('io_' + p, 'Templates/IO/Faceplates/' + model, params={'cardPath': p}, ...)`.
- **Embedded:** no `ia.display.view` in the library points at these views. They are opened by name only.
- **Params:** `cardPath` only.
- **Generated view:** no. As for the discrete faceplates, `Docks/IOCard` is generated by `generator/docks/build_docks.py` (`io_card()`), and no generator writes these faceplate files.

The rest of this document applies to all three views. The header, the custom properties and the body repeater binding are identical in all three, except for the row template that the repeater embeds. The status bar is identical except that AMO0802 adds the `RO` caption. The column headers are static text and differ as shown in the table: the AO row has no `Limit` (Flags) cell, and the TEMP row has no `Range` (bar) cell.

## How it operates

- **Header, status bar and health.** The same as the discrete faceplates: `Instance` line, `MODULE HEALTHY` / `MODULE FAULT` / `COMMS?`, and the `Module: <text>` diagnostic line. See [Discrete_Cards](Discrete_Cards.md) for the bindings and the notes on the module tags.
- **Column header row.** `ColHeader` holds static labels: Ch, Loop tag, Description, Raw, Value, Units, then Range and/or Limit, then Health. The labels differ by view, as listed in the Differences table.
- **Rows.** `Rows` is a flex repeater that builds 8 rows (channels 0 to 7). Each row gets `cardPath`, `ch`, `chFolder` (`CHnn`) and `alt` (true on odd channels, for row shading). The row template is the one listed in the Differences table. Row behaviour (value, bar, flags, health) is in the AnalogRow doc.
- **Read-only.** The AMO view carries the `RO` caption ("Read-only: the PLC drives these outputs"). No binding, script or transform in the three views writes a tag.
- **Close.** The `Close` button calls `system.perspective.closePopup('')`, as in the discrete faceplates.
- **Security.** No role check and no audit, because nothing is written.

## Scripts reference

Each view has one event script (`root/Header/Close`) and one transform script on the `Rows` repeater (T1). There are no custom methods, message handlers, onChange scripts or view scripts.

```python
	system.perspective.closePopup('')
```

Explanation: as for the discrete `Close` button. It calls `system.perspective.closePopup` with an empty id, which closes the popup the calling component is in (this faceplate).

Transform T1 (`Rows`, same in all three views):

```python
	n = 8
	p = str(value or '')
	if not p:
		return []
	return [{'cardPath': p, 'ch': i, 'chFolder': 'CH%02d' % i, 'alt': (i % 2 == 1)} for i in range(0, 8)]
```

Explanation: if `cardPath` is blank, return an empty list. Otherwise return eight instance dicts, one per channel 0 to 7, each with `cardPath`, `ch`, `chFolder` (`CHnn`) and `alt` (true on odd channels). `n = 8` is set but never used.

No `efc.ui` library function is called from these views.

## Tag members used

As for the discrete faceplates, there is no PCLib definition for these members. `types/PCLib_Members.csv` has no `Module/*`, `CH*`, `Doc/*` or `HMI/*` entries, and `tags/` has no IO tags. Types are inferred from use. The channel members are read by the row parts, see [AnalogRow](../Parts/AnalogRow.md).

| Member | Access | Data type | Meaning |
|---|---|---|---|
| `Module/MOD_ERROR` | read | BOOL (inferred) | Module error. Drives MODULE HEALTHY / MODULE FAULT. Quality also drives COMMS?. |
| `Module/HMI/DiagText` | read | STRING (inferred) | Module diagnostic text for the status bar. |
| `Rack` | read | INT (inferred) | Rack number in the header. |
| `Slot` | read | INT (inferred) | Slot number in the header. |

Read only. No write path.

## Notes and open questions

- **AMO0802 channel count.** The view shows 8 AO rows and the description says "8 AO". The fixture in `generator/render_views.py` (`IO_CARDS`, and `io_fixture`) creates only 2 channels for BMXAMO0802 (`FCV-201`, `PCV-202`). Rows 2 to 7 would read tags the fixture does not create (not checked at runtime). Open question: check the model and channel count against the hardware list.
- **ART0814 channels.** The fixture populates six channels (TT-301 to TT-306) and leaves two spare. The view has 8 rows. Consistent with the fixture, but not verified against the hardware list.
- **Preview default.** All three default to `[default]IO_Demo/Rack0/R0S5` (the AMI card address), including AMO, whose fixture slot is R0S6. Preview only, since the dock always passes `cardPath`.
- **READ_STS caption.** Static text with no binding. Not defined in the repo. Open question (see the discrete doc).
- **Unused variable.** `n = 8` in the transform is never used. Cosmetic.
- **Column header cells.** The AMO view has no `Limit` header and the ART view has no `Range` header, which matches the row templates. Not a defect, but the header and row must change together if a row template changes.
- **Dock doc.** [IOCard](../../../Docks/IOCard.md) covers the dock.
